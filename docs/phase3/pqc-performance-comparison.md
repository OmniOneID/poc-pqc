# OpenDID PQC 성능 비교 결과

## 1. 요약

본 측정 결과, **PQC와 Classic 사이에 사용자 체감 수준의 의미 있는 속도 차이는 확인되지 않았다.** 일부 구간에서 평균값 차이가 보이긴 하나 측정 분산 범위 안에 있거나, 분포 중심값(P50) 기준으로는 두 모드가 사실상 동일하다.

- **키교환(D)**: 평균만 보면 **PQC가 약 19 ms 빠르게** 측정되었으나, P50 기준으로는 두 모드 차이가 약 3 ms에 불과하다. Classic 측 outlier 영향(최댓값 959 ms)이 평균을 끌어올린 결과로, **두 모드는 사실상 동일하다**고 보는 편이 옳다.
- **VC 발급(B), 5클레임**: 평균 **+1.2초, P50 +1.1초로 PQC가 일관되게 느리게 측정**되었다. 본 측정에서 PQC와 Classic 사이의 차이가 분명히 관찰된 유일한 구간이다.
- **VC 발급(B), 50/100클레임**: 평균 차이가 −400 ~ +600 ms로 방향이 일관되지 않으며, 분산 범위 안에 있다. P50 기준 차이도 −319 ~ +509 ms 수준으로 의미 있는 차이로 보기 어렵다.
- **VP 제출(C), 5/50/100클레임**: 모든 구간에서 평균과 P50 차이가 ±200 ms 이내로 사실상 차이가 없다.

즉, **이번 측정 결과만 두고 보면 PQC 도입에 따른 사용자 체감 지연은 VC 발급 저클레임 구간(약 +1초)을 제외하면 거의 없다.** 발급 저클레임 +1초도 ML-DSA-44 단일 서명 비용으로는 설명되지 않는 크기여서, 발급 플로우의 비-PQC 구간 특성에서 비롯된 차이일 가능성을 함께 검토할 필요가 있다.

핵심 구간의 대표 수치는 다음과 같다.

| 구간 | Classic 평균 | PQC 평균 | 절대 증가량 | 오버헤드 |
|------|-------------|---------|-----------|---------|
| 키교환 (왕복 시간 평균) | 62.5 ms | 43.5 ms | −19.0 ms | −30.4 % |
| VC 발급 — 5클레임 | 1982 ms | 3173 ms | +1191 ms | +60.1 % |
| VC 발급 — 50클레임 | 3713 ms | 3313 ms | −400 ms | −10.8 % |
| VC 발급 — 100클레임 | 5502 ms | 6125 ms | +623 ms | +11.3 % |
| VP 제출 — 5클레임 | 2894 ms | 2899 ms | +5 ms | +0.2 % |
| VP 제출 — 50클레임 | 4671 ms | 4703 ms | +32 ms | +0.7 % |
| VP 제출 — 100클레임 | 7555 ms | 7393 ms | −162 ms | −2.1 % |

## 2. 측정 방법

### 2.1 시나리오

| 시나리오 | 측정 대상 | 목적 |

| **C** | VP 제출 시 클레임 수별 처리 시간 (5/50/100) | 제출 경로가 클레임 수 증가에 따라 어떻게 변하는지 확인 |

## 3. 측정 결과

측정 결과는 *키교환 → VC 발급 → VP 제출* 순으로 정리하였다.

### 3.1 시나리오 D — 키교환 단독

| 측정 항목 | Classic (ECDH) | PQC (ML-KEM-768) | 절대 증가량 |
|----------|----------------|------------------|-----------|
| 앱 왕복 시간 (평균) | 62.50 ms | 43.49 ms | −19.01 ms |
| 앱 왕복 시간 (P50) | 34.62 ms | 37.39 ms | +2.77 ms |
| 앱 왕복 시간 (P95) | 185.23 ms | 64.92 ms | −120.31 ms |
| 앱 왕복 시간 (최댓값) | 959.21 ms | 584.92 ms | −374.29 ms |
| 서버 처리 시간 (평균) | 11.61 ms | 10.39 ms | −1.22 ms |
| 네트워크 시간 (평균) | 50.89 ms | 33.11 ms | −17.78 ms |
| 클라이언트 암호 연산 (평균) | 28.79 ms | 20.77 ms | −8.02 ms |

평균과 P95에서는 PQC가 더 빠르지만, **P50 기준으로는 두 모드 차이가 약 3 ms로 사실상 동일**하다. Classic 측 분포의 꼬리(최댓값 959 ms)가 평균과 P95를 끌어올린 결과로, **양 모드가 동등하다**고 해석하는 것이 적절하다.

### 3.2 시나리오 B — VC 발급 클레임 수 스케일링

| 클레임 수 | Classic 평균 | Classic P50 | Classic P95 | PQC 평균 | PQC P50 | PQC P95 | 평균 증가량 | P50 증가량 |
|----------|-------------|-------------|-------------|---------|---------|---------|------------|------------|
| 5 | 1982 ms | 1839 ms | 2759 ms | 3173 ms | 2967 ms | 3969 ms | +1191 ms | +1128 ms |
| 50 | 3713 ms | 3390 ms | 5009 ms | 3313 ms | 3071 ms | 4844 ms | −400 ms | −319 ms |
| 100 | 5502 ms | 5213 ms | 7174 ms | 6125 ms | 5722 ms | 7760 ms | +623 ms | +509 ms |

5클레임에서는 평균과 P50 모두 PQC가 약 1.1초 느리게 측정되었다. 50클레임에서는 PQC가 오히려 약간 빠르고, 100클레임에서는 다시 PQC가 약 0.5초 느리다. **방향성이 일관되지 않으며, 분포의 꼬리(최댓값 11~13초)가 50/100클레임 구간에서는 평균을 좌우할 정도로 크다.**

### 3.3 시나리오 C — VP 제출 클레임 수 스케일링

| 클레임 수 | Classic 평균 | Classic P50 | Classic P95 | PQC 평균 | PQC P50 | PQC P95 | 평균 증가량 | P50 증가량 |
|----------|-------------|-------------|-------------|---------|---------|---------|------------|------------|
| 5 | 2894 ms | 2752 ms | 3648 ms | 2899 ms | 2677 ms | 4071 ms | +5 ms | −74 ms |
| 50 | 4671 ms | 4508 ms | 5587 ms | 4703 ms | 4481 ms | 6009 ms | +32 ms | −27 ms |
| 100 | 7555 ms | 7373 ms | 8437 ms | 7393 ms | 7274 ms | 7885 ms | −162 ms | −98 ms |

**모든 클레임 구간에서 평균·P50 차이가 ±200 ms 이내로 사실상 동일**하다. VP 제출 경로에서는 PQC와 Classic이 구분되지 않는 수준의 동등한 성능을 보인다.

## 4. 분석

### 4.1 키교환 vs 서명 — 어느 쪽 PQC 오버헤드가 더 큰가

각 구간의 P50 기준 절대 증가량을 비교하면 다음과 같다.

| 연산 | Classic P50 | PQC P50 | P50 증가량 |
|------|-------------|---------|------------|
| 키교환 (D) | 34.62 ms | 37.39 ms | +2.77 ms |
| VC 발급 — 5클레임 | 1839 ms | 2967 ms | +1128 ms |
| VC 발급 — 50클레임 | 3390 ms | 3071 ms | −319 ms |
| VC 발급 — 100클레임 | 5213 ms | 5722 ms | +509 ms |
| VP 제출 — 5클레임 | 2752 ms | 2677 ms | −74 ms |
| VP 제출 — 50클레임 | 4508 ms | 4481 ms | −27 ms |
| VP 제출 — 100클레임 | 7373 ms | 7274 ms | −98 ms |

해석: **VC 발급 5클레임 외에는 PQC와 Classic의 P50 차이가 모두 ±수백 ms 이내로 작거나 PQC가 오히려 빠르다.** 키교환은 P50 차이가 3 ms 수준으로 사실상 동일하다. ML-DSA-44 서명·ML-KEM-768 키교환의 단일 연산 비용 자체는 한 자릿수 ms 수준이므로, 이 측정에서 관찰되는 ±수백 ms 단위 차이는 PQC 알고리즘 자체보다는 **OpenDID 발급/제출 플로우의 비-PQC 구간 특성과 측정 환경 변동성에 의한 결과**로 보는 편이 자연스럽다.

### 4.2 클레임 수 스케일링

5클레임에서 100클레임까지 P50 기준 평균 증가율을 비교하였다.

| 시나리오 | Classic 기울기 (ms/claim) | PQC 기울기 (ms/claim) |
|---------|--------------------------|----------------------|
| B (발급) | 35.5 | 29.0 |
| C (제출) | 48.6 | 48.4 |

해석: **두 시나리오 모두 두 모드의 클레임 스케일링 기울기가 거의 같다.** B(발급)는 35 vs 29 ms/claim, C(제출)는 48 vs 48 ms/claim. 클레임 수 증가에 따른 처리 비용은 PQC와 Classic이 동일한 수준으로 증가한다.

## 5. 결론

### 5.1 종합 판단

본 측정 기준으로 **PQC 적용에 따른 OpenDID의 사용자 체감 속도 변화는 VC 발급 5클레임 구간(P50 +1.1초)을 제외하고 확인되지 않았다.** 키교환과 VP 제출 시나리오, 그리고 VC 발급 50/100클레임 구간에서는 두 모드 차이가 측정 분산 범위 안에 있다.

판단 기준 (사용자 체감 지연 임계값):

| 지연 | 사용자 체감 |
|------|-----------|
| < 100 ms | 거의 인지하지 못함 |
| 100 ~ 300 ms | 인지 가능하나 자연스러움 |
| 300 ms ~ 1 s | 명확히 느림 |
| > 1 s | 답답함 / 흐름 끊김 |

### 5.2 판단 근거

각 구간의 PQC P50 증가량을 위 임계값과 함께 정리하면 다음과 같다.

| 구간 | P50 증가량 | 사용자 체감 임계 | 비고 |
|------|-----------|-----------------|------|
| 키교환 | +2.77 ms | 거의 인지 불가 | 사실상 동일 |
| VC 발급 (5클레임) | +1128 ms | 답답함 / 흐름 끊김 | **본 측정에서 유일하게 일관되게 나타난 차이** |
| VC 발급 (50클레임) | −319 ms | — | PQC가 약간 빠름, 의미 있는 차이로 보기 어려움 |
| VC 발급 (100클레임) | +509 ms | 명확히 느림 | 50클레임 결과와 방향이 반대, 분산 범위로 해석 |
| VP 제출 (5클레임) | −74 ms | — | 사실상 동일 |
| VP 제출 (50클레임) | −27 ms | — | 사실상 동일 |
| VP 제출 (100클레임) | −98 ms | — | 사실상 동일 |

### 5.3 도입 시 고려 사항

- **VC 발급 저클레임 구간.** 본 측정에서 PQC가 일관되게 느리게 나타난 유일한 구간이다(P50 +1.1초). ML-DSA-44 단일 서명 비용으로는 설명되지 않는 크기여서, 발급 플로우의 비-PQC 구간 특성(DB 처리, 다중 서버 호출 등)을 함께 점검할 필요가 있다. 사용자 체감 완화가 필요하다면 진행 표시 강화, 비동기 처리, 사전 계산 가능 구간 분리 등을 검토할 수 있다.
- **VC 발급 50/100클레임 구간.** 평균 차이가 −400 ~ +600 ms로 방향이 일관되지 않다. 측정 분산 범위 안에 있어 PQC 도입의 영향으로 단정하기 어렵다.
- **키교환·VP 제출 전체.** 두 모드가 사실상 동일한 성능을 보였다. PQC 도입에 따른 추가 영향이 거의 없다고 볼 수 있다.
- **네트워크 조건.** PQC 페이로드 크기 증가(서명 약 2.4 KB, 공개키 약 1.3 KB)는 본 측정의 로컬 LAN에서는 두드러진 영향을 만들지 못했다. 셀룰러나 원거리 네트워크에서는 영향이 더 커질 수 있어 별도 측정이 필요하다.
- **분산 관리.** Classic·PQC 모두 일부 측정에서 최댓값이 11~13초까지 상승하는 등 꼬리 분포가 길다. PQC 도입 여부와 별개로 발급 경로 안정화가 필요하다.

## 6. 한계

- **단일 단말 측정.** 다른 SoC(특히 저가형 ARM)에서는 ML-DSA-44/ML-KEM-768의 NTT 연산 비용이 다를 수 있다.
- **로컬 LAN 환경.** 셀룰러/원거리 네트워크에서는 PQC 페이로드 크기 증가의 영향이 더 커질 수 있다.
- **잔존 분산.** 워밍업 5회를 일관 적용하였음에도 일부 측정에서 최댓값이 평균의 2~3배까지 상승하는 long-tail 분포가 남아 있다(B 50/100클레임의 max 11~13초). 서버 GC, DB 락, 네트워크 변동 등 시스템 측 분산 요인이 잔존하는 것으로 보인다.
- **회차 간 시간 간격.** 회차들이 약 3시간(06:31~09:14)에 걸쳐 측정되어, 회차 간 서버 캐시·DB 상태가 동일하지 않을 가능성이 있다. Classic ↔ PQC 인터리빙 측정으로 시간 상관 편향을 더 줄일 수 있다.
- **측정 범위 외.** 배터리 소모, 메모리 사용량, 동시 다중 사용자 부하, 콜드 스타트 비용은 본 측정에 포함되지 않는다.
